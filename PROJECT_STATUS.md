# PROJECT_STATUS — WalletWeb

Fecha: 2026-11-16 · Versión 1.0.0 ("v1 local")

## Decisión principal
El documento pide primero un Hito 0 (solo diseño) y una arquitectura React + FastAPI + PostgreSQL con Google OIDC. El usuario pidió una app usable en el iPhone ya. Se construyó una **v1 100 % local** (sin servidor) que cubre el núcleo financiero de los hitos 3, 4, 5 (sin push), 6, 8 y parte de 9 y 10. Sirve como prototipo funcional y como especificación ejecutable del modelo de datos para la futura versión con backend.

## Revisión de seguridad y privacidad (v1.34)
- **Repositorio público**: GitHub Pages gratis exige repositorio público, así que el código es visible. Se quitaron datos personales que habían quedado publicados (un correo en este archivo, el nombre de una persona y los datos de la factura real usada para calibrar el escáner) y se preparó un **historial de git limpio** (sin esos datos en los commits anteriores). Reemplazar el historial publicado en GitHub borra el anterior para todos, así que queda **pendiente de la autorización del dueño**; mientras tanto esos datos siguen visibles en commits viejos. Las pruebas usan datos ficticios. `.gitignore` bloquea fotos, PDF, CSV y copias de la app.
- **Datos de la app**: viven solo en el teléfono (IndexedDB + copia espejo en localStorage) y, si se conecta, las facturas en el Drive del usuario. Ni el repositorio ni el sitio publicado contienen datos; quien abre el enlace ve una app vacía con su propio almacenamiento.
- **Inyección de HTML**: prueba dinámica con cargas maliciosas en todos los textos (todas las pantallas, hojas, importación CSV y texto pegado): sin hallazgos. Los enlaces de Drive se validan también al mostrarse. Las copias restauradas se revisan antes de aplicarse (`C.unsafeStateFields`: identificadores, fechas, colores y números internos que se insertan sin escapar).
- **Perfiles**: desde Demostración ya no se pueden editar ni eliminar otros perfiles; eliminar un perfil exige estar dentro de él (con su PIN) y confirmación escrita; aviso si el perfil no tiene PIN.
- **CSP** (`index.html`): `script-src 'self'` sin código en línea; `object-src`, `base-uri`, `form-action` y `frame-src` en `'none'`. Se corrigió el botón "Reintentar" de la pantalla de error, que usaba `onclick` en línea y la CSP lo bloqueaba.
- **No se resuelve con código**: (1) la cuenta de GitHub: quien la controle puede publicar código que lea los datos del teléfono en la siguiente actualización → verificación en dos pasos obligatoria; (2) todos los sitios de GitHub Pages de una misma cuenta comparten origen (`usuario.github.io`) y por tanto el almacenamiento → no publicar otros sitios con Pages en esa cuenta, o mover WalletWeb a un origen propio (organización de GitHub, Cloudflare Pages o dominio propio) con copia y restauración; (3) los datos no están cifrados dentro del navegador (punto ya documentado).

## Riesgos conocidos
0. **Google Drive (v1.33)**: depende de que Google mantenga el comportamiento de las aplicaciones web de Apps Script (POST → redirección a `script.googleusercontent.com` con CORS). Cuotas de Apps Script para cuentas gratuitas: si se alcanzan, la app espera y reintenta. Si el usuario borra o despublica el script, la app muestra el error y no pierde nada local.
1. **Pérdida de datos** si se borra la app o Safari limpia el almacenamiento → copia semanal + aviso + instantáneas diarias + `navigator.storage.persist()`.
2. Los datos del ícono instalado y de Safari están separados en iOS.
3. Sin sincronización entre iPhone y Mac (solo vía copia/restauración).
4. Los festivos se calculan por ley; si el Gobierno cambia uno, usar excepciones manuales.
